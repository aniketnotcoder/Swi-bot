# Storelex-only safe cutover

`npm start` now boots `storelex-bot.js`, not the legacy `index.js`. Old Telegram buttons receive a disabled response, the old Mini App and checkout HTTP routes are not served, and no Storelex payment/order mutation is called. Legacy source and stored data are preserved for rollback; do not run `node index.js` or the separate `bossbot` simultaneously. Only one polling instance per Telegram bot token.

Host secrets: `BOT_TOKEN`, numeric `BOSS_ID`, `STORELEX_USER_KEY`; optionally `STORELEX_API_BASE_URL` (default `https://storelex.store/swiggy_web/api`). Set `PORT` only if the host needs a health endpoint. Never paste keys into chat or Git. Rotate any key previously disclosed in chat. The old `BOSS_SECRET`, vault/UPI variables are not used by this runtime.

Startup makes an authenticated, read-only `/me` request and fails closed if authentication is unavailable. After deploy, boss sends `/status` for another `/me` check, or `/sessions` for a read-only count (never sends session details), or `/cartcheck` for the top-level field names of a read-only `/cart/state` response (never sends cart values), or `/recent` for a read-only count of the last hour's orders (without order details). Public OpenAPI at `https://storelex.store/swiggy_web/openapi.json` confirms these routes but declares arbitrary checkout objects. The separately supplied API notes document preparation request bodies and sample responses; they do not prove the live payable unit or safe placement idempotency. A connected response proves only the API credential and endpoint, NOT cart/import/checkout functionality. Boss-only private-chat preparation is available via `/account <10-digit mobile>` → `/address <Swiggy address link>` → `/group <Swiggy group cart link>` → `/bill`. It calls the documented address-by-link, group import and repricing endpoints, validates essential IDs/coordinates/items and reports only counts, never raw personal data. Importing a group cart can modify the selected remote cart, so use a test account first. Drafts are process-memory only and disappear on restart. Checkout/place, payment and exact payable amounts remain disabled until a real repriced response is independently checked against the Storelex UI. The supplied documentation included a key-like example: rotate any real key exposed in attachments/chat before deployment. Health JSON intentionally reports `ordersEnabled:false`. Old messages may retain visible inline buttons, but pressing them cannot run old actions through this process.

Deploy a Docker worker/service with `npm start`; Vercel serverless functions are not compatible with this polling process. To avoid misleading live traffic, do not deploy until the rotated Storelex key is configured and a single bot instance is selected. Existing persistent data is not deleted.
