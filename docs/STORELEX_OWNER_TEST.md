# Storelex owner-only live UPI test

This is a **real order / real payment attempt**, NOT a sandbox. No customer can access it; only numeric `BOSS_ID`/`BOSS_IDS` in private Telegram chat. Owner Pay now activates automatically when an actual dedicated `DATA_DIR` volume is detected (Render defaults to `/app/data`); `STORELEX_OWNER_PAY_TEST=0` explicitly disables it. An ordinary directory baked into Docker does not enable Pay. If the live service has no mounted volume, add a persistent disk at `/app/data` and set `DATA_DIR=/app/data`. The Render blueprint provides both. `/status` and the bill explain when Pay is unavailable. Run one bot instance. Never test with a real customer order without consent.

Owner can paste a Swiggy address link and group-cart link as ordinary messages, in either order or together. The bot picks a usable Storelex account (preferring zero-order) unless `/account <mobile>` explicitly selects one; it shows the last four digits, parses the address, imports the cart, and returns the bill automatically. Inspect it against Storelex UI and tap **Confirm bill & Pay ₹...** (or use `/pay <exact rupee payable>`). This is a single confirm+pay operation. `/whoami` shows the Telegram numeric ID if `BOSS_ID` does not match. Only a unique final `To Pay`, `Total Payable`, or `Grand Total` line explicitly formatted as `₹...` matching the entered amount allows the request. Other formats fail closed. The provider may create a real order; if successful and it returns a UPI intent, the bot sends the provider-only QR. QR sent != paid. `/paystatus` reads Storelex payment status for the current cart; only `PAID` from the provider is confirmed. Unknown/unavailable results must be checked manually. Unknown/timeout/amount_changed responses block retries; never retry `/pay` on the same cart. A private on-disk exclusive-create journal keyed by account+cart id blocks double placement across restarts; preserve it during deploys. New cart IDs are not automatically guaranteed safe against duplicate real orders—reconcile the first attempt before a new cart. The bot never asks for card/CVV.

Do not enable for all users after one successful test: payment status, settlement, order tracking, concurrency, durability and response variants must be separately validated. No public rollout switch is implemented. Never paste the access key into chat; rotate a key exposed in attached example docs.
