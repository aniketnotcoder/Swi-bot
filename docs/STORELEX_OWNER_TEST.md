# Storelex owner-only live UPI test

This is an opt-in **real order / real payment attempt**, NOT a sandbox. No customer can access it; only numeric `BOSS_ID` in a private Telegram chat. Keep `STORELEX_OWNER_PAY_TEST` unset/0 for the normal safe mode. To opt in, use `STORELEX_OWNER_PAY_TEST=1` with a **persistent, private absolute `DATA_DIR`** (Render disk mount `/app/data`; verify it actually persists). Run one bot instance. Never test with a real customer order without consent.

Sequence: `/account <mobile>` → `/address <Swiggy address link>` → `/group <Swiggy group cart link>` → `/bill`. Inspect the bill and compare against Storelex UI. `/pay <exact rupee payable>` is the single confirm+pay operation. Only a unique final `To Pay`, `Total Payable`, or `Grand Total` line explicitly formatted as `₹...` matching the entered amount allows the request. Other formats fail closed. The provider may create a real order; if successful and it returns a UPI intent, the bot sends the provider-only QR. QR sent != paid. `/paystatus` reads Storelex payment status for the current cart; only `PAID` from the provider is confirmed. Unknown/unavailable results must be checked manually. Unknown/timeout/amount_changed responses block retries; never retry `/pay` on the same cart. A private on-disk exclusive-create journal keyed by account+cart id blocks double placement across restarts; preserve it during deploys. New cart IDs are not automatically guaranteed safe against duplicate real orders—reconcile the first attempt before a new cart. The bot never asks for card/CVV.

Do not enable for all users after one successful test: payment status, settlement, order tracking, concurrency, durability and response variants must be separately validated. No public rollout switch is implemented. Never paste the access key into chat; rotate a key exposed in attached example docs.
